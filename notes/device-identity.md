# Device identity: CUDA ordinals and UUID requests

<!-- markdownlint-disable-next-line MD036 -->
_Last verified: 2026-11-02 against the unmanaged-process working tree_

## Summary

Protocol v7 retains UUIDs for every GPU request. Local `--gpus` indices come
from the client's CUDA environment, not the daemon's numbering. Dense
daemon indices remain in scheduler state and display metadata only.

## Details

### Actual CUDA visibility

`device_visibility::VisibleDevices::probe` uses cudarc's safe result API to
runtime-load CUDA, initialize the driver and enumerate ordinal UUIDs. It
does not create a context, stream or device memory. CUDA applies device
ordering, numeric/UUID `CUDA_VISIBLE_DEVICES`, and container access limits.
Empty/negative visibility never becomes an unrestricted request. Driver
loader failures are contained as errors; NVML indices are not a fallback.

NVML 0.13 provides MIG inspection. Each visible device is checked for MIG
handle identity and current MIG mode. A feature returning `NotSupported`
is absent on that GPU; unavailable/failed inspection is not assumed safe.
Config and device metadata use only the verified CUDA-visible UUID subset.
The daemon sorts it by NVML index and assigns dense logical display indices.

CUDA caches its device view per process. Probe before other CUDA use and
do not mutate environment variables afterward. Docker requires both
`compute` (CUDA driver) and `utility` (NVML) capabilities. The dynamically
loaded APIs need no toolkit or build-time driver linkage. Rust >= 1.88 is
required by the selected dynamic-loading dependency.

### Request and grant boundaries

`cli_options::build_acquire` parses options, but its local numeric lists
are not wire requests. `VisibleDevices::prepare_acquire` resolves ordinals
to UUIDs, validates explicit UUID membership and constrains counts to the
actual view. Empty candidates and legacy numeric wire selection are rejected
by the protocol-v7 codec. Config remains UUID-only.

`Client::acquire` probes on a blocking worker and uses that view throughout
acquisition. An injected trusted provider may use `acquire_with_visibility`.
The CLI prepares before connecting. Count grants must have the requested
size and stay in candidates; explicit grants must preserve UUID order too.
Invalid grants, terminal codec/read errors and unexpected replies shut down
the connection so the daemon sees EOF and releases the reservation even if
the client object remains alive. Do not rely on Framed to close its socket
when its decoder enters an errored state.

Candidate UUIDs outside management are intersected out; explicitly requested
unmanaged UUIDs are denied. The daemon cannot independently attest a peer's
CUDA view; these checks coordinate cooperating clients, not GPU access control.

### Fixtures and testing

Current fixtures are `protocol_v7*.txt`, generated by the independent
`scripts/gen-golden-v7.py`. The v3 to v6 fixtures are kept unchanged as a
record of earlier layouts and are not tested; their generators stay because
`gen-golden-v7.py` builds on them. Older peers are rejected at handshake.

Snapshot unit tests cover order, bounds, duplicates, count intersections and
grant validation. CLI and daemon startup tests inject a standalone mock
CUDA/NVML cdylib into subprocesses, without a production testing bypass.
Its unsafe mock ABI is not part of a workspace module or shipped binary.

The current tree passed 345 tests in Debug and Release, with repeated Debug
runs, rustfmt, Clippy with warnings denied and documentation checks. Real
RTX PRO 6000 devices were used to verify numeric reordering, UUID membership,
count intersection, daemon visibility/config restrictions and v3 rejection.
The latest Docker image passed both CUDA-mask and Docker-device-subset cases;
its daemon PID did not appear in the host's compute-process query after
enumeration. Actual MIG hardware was not exercised; positive/error MIG
branches are covered by isolated driver doubles.

## Why

CUDA ordinals differ between environments and can differ from NVML even on
the host. Resolving them where the command runs and transmitting UUIDs
avoids accidentally reserving another physical GPU. Requiring count
candidates also prevents an empty or restricted CUDA view from being widened
by the daemon. Context-free enumeration avoids occupying a GPU merely to
discover its identity, which would interfere with daemon process observation.
